# 带 LC_ENCRYPTION_INFO 的 Mach-O：不解密、不运行的静态分析方案

面向审查人员的方法论与报告结构设计。本文档只描述**能从磁盘字节与加载命令中确定的事实**，
不包含任何脱壳、内存 dump 或运行时插桩能力，配套代码也不提供这类功能。

## 1. 目标与边界

**能做什么**

- 解析 mach 头、全部 load command，以及它们声明的偏移/尺寸/保护属性；
- 用 `cryptoff/cryptsize/cryptid` 与各 segment、section、入口、链接编辑数据的文件范围做交叉判断；
- 区分三类字节：**声明加密**、**范围冲突/越界**、**磁盘上确实可读的明文**；
- 对读不到内容的部分，报告其*位置与元数据*，并显式标注“内容不确定”。

**不做什么（明确排除）**

- 不恢复密文对应的明文，不绕过 FairPlay/DRM，不附加调试器，不启动进程；
- 不依据熵高、某条 flag 或某个节名就断言“使用了某壳”；
- 不把“当前读不到代码”当作“没有代码/没有恶意逻辑”。

## 2. 为什么头部信息在加密后仍可信

`LC_ENCRYPTION_INFO(_64)` 描述的是**文件内一段字节窗口** `[cryptoff, cryptoff+cryptsize)`，
加密按页作用于该窗口；mach 头与 load command 位于 `__TEXT` 起始的头部页，始终以明文存在，
否则加载器无法映射镜像。macholib 的读取路径恰好只在这些明文区域建立可信事实：

- `macholib/MachO.py` 的 `MachOHeader.load` 用 `fileview` 限定窗口，逐条 `from_fileobj`
  读取 mach 头与 load command（`MachO.py:241` 起）。这一步不触碰加密页内容。
- segment 的 section 数据通过 `fh.seek(seg.offset); fh.read(seg.size)` 直接读原始字节
  （`MachO.py:316-319`）。**macholib 不区分明文与密文**——若该节落在加密窗口内，
  读到的就是密文。因此“读到了字节”不等于“读到了有意义的内容”，必须再做范围交叉判断。
- `macholib/SymbolTable.py` 按 `symoff/stroff` 原始偏移读 nlist 与字符串表
  （`SymbolTable.py:43-66`）。这些数据是否可读，取决于其偏移是否在加密窗口内，
  而不是取决于 macholib 能否“打开文件”。
- 依赖名（`LC_LOAD_DYLIB` 等）是 load command 的内联字符串，随头部一起保持明文，
  由 `walkRelocatables`（`MachO.py:353`）解析，始终可读。

结论：**macholib 提供的是结构与偏移层面的事实；字节是否有意义由本方案的范围分类决定。**

## 3. 三类加密状态的判定规则

定义加密窗口 `C`：仅当存在加密命令、`cryptid != 0` 且 `cryptsize > 0` 时 `C` 为有效半开区间
`[cryptoff, cryptoff+cryptsize)`；否则视为“无活动加密窗口”。对任意文件区间 `R`：

| 判定 | 条件 | 含义 |
| --- | --- | --- |
| fully-encrypted | `R ∩ C == R` | 整个区间在窗口内，磁盘字节为密文，不可解释为代码/字符串 |
| partially-encrypted | `R ∩ C` 非空且小于 `R` | 同一结构跨明文/密文边界，需分别记账 |
| fully-clear | `R ∩ C == ∅` | 磁盘明文，可直接解析 |
| zerofill/no-file-bytes | `S_ZEROFILL` 或 `offset==0` | 仅占虚拟内存，文件中无字节，**不计入明文也不计入密文** |
| no-encryption-command | 无活动窗口 | 等价于全部磁盘字节可读（报告中归一化为 fully-clear） |

实现见 `demo/ranges.py` 的 `classify_against`，区间一律使用**文件偏移**而非虚拟地址。

### 3.1 声明本身的自洽性检查（不依赖解密）

- `cryptid != 0 && cryptsize == 0`：矛盾声明，标记 `inconsistent declaration`；
- `cryptid == 0 && cryptsize != 0`：休眠命令（App 脱壳后常见形态），磁盘为明文，标记 `dormant`；
- `cryptoff + cryptsize > 文件大小`：窗口越界，标记 `overruns file`；
- 窗口与 `__LINKEDIT` 重叠：dyld 元数据/签名在磁盘上将不可读，标记范围冲突；
- 出现多条加密命令：标记 `multiple encryption commands`。

这些都是**结构性证据**，可直接写入报告，无需对内容做任何猜测。

## 4. 报告结构设计

顶层按架构（fat 则每 slice 一份）组织，每个架构包含以下分节。每节都带 `certainty`/
`coverage` 字段，使“确定事实”与“不确定内容”在数据层面可区分（机器可读样例见
`demo/sample_report.json`）。

1. **identity**：magic/位宽、字节序、cputype/cpusubtype、filetype、头部 flags
   （如 `MH_PIE`、`MH_NO_HEAP_EXECUTION`）。来源：mach 头明文，**始终可报告**。
2. **encryption**：命令名、`cryptoff/cryptsize/cryptid`、是否活动、有效窗口、自洽性诊断。
   来源：加密命令本身（明文），**始终可报告声明**；“是否真有密文”由自洽性检查限定。
3. **dependencies**：`LC_LOAD_DYLIB/LC_LOAD_WEAK_DYLIB/LC_REEXPORT_DYLIB` 等名称与类型。
   内联于 load command，**始终可报告，无需标不确定**。
4. **entry**：`LC_MAIN.entryoff` 或 `LC_UNIXTHREAD` 线程态入口。
   - 入口**位置/偏移始终可报告**；
   - 入口指向的指令是否可读，取决于该偏移是否落在 `C` 内：落在窗口内则
     `instructions_readable=false`，只能报告地址，不能反汇编。
5. **segments / sections**：每个 segment 的文件范围、VM 范围、`initprot/maxprot`，
   以及每个 section 的加密/明文字节计数与（仅作描述用的）熵值。zerofill 单独标注。
6. **symbols**：`LC_SYMTAB/LC_DYSYMTAB` 的 `nsyms`、符号表/字符串表范围与覆盖状态。
   - 元数据（数量、索引、范围）**始终可报告**；
   - 仅当 nlist 与字符串表都在窗口外时 `names_resolvable=true`，才给出符号名；
   - 否则标记 `metadata-only`，不得把乱码当符号，也不得断言“无符号”。
7. **linkedit**：`LC_DYLD_INFO(_ONLY)` 的 rebase/bind/weak/lazy/export 各子区间、
   `LC_DYLD_EXPORTS_TRIE`、`LC_DYLD_CHAINED_FIXUPS`、`LC_CODE_SIGNATURE`，逐区间给覆盖状态与
   `parseable`。落在窗口内即标记不可解析，而不是忽略该数据。
8. **range_conflicts / confidence_notes**：汇总越界、重叠、矛盾声明等所有需要人工复核的点。

### 4.1 熵的正确用法

熵（`ranges.shannon_entropy`，bits/byte）只作为**描述性指标**并列展示，不作为分类器输入：
高熵可能来自加密页、压缩资源或随机数据，低熵也不代表无壳。是否“加壳/用了哪种保护”
必须结合加密命令、段保护、链接编辑结构等多重证据，并在证据不足时保持“不确定”。

## 5. 各信息项：何时可报告、何时标不确定

| 信息项 | 位置来源 | 内容可读条件 | 处理方式 |
| --- | --- | --- | --- |
| 架构/字节序/filetype/flags | mach 头 | 恒可读 | 直接报告 |
| 加密声明三要素 | 加密 load command | 恒可读（声明层面） | 报告 + 自洽性诊断 |
| 依赖库与链接类型 | load command 内联字符串 | 恒可读 | 直接报告 |
| 入口位置 | `LC_MAIN`/`LC_UNIXTHREAD` | 恒可读 | 报告偏移 |
| 入口指令/反汇编 | 入口指向的代码页 | 该偏移在 `C` 外 | 窗口内则仅报地址并标不确定 |
| section 元数据（偏移/尺寸/属性） | segment command | 恒可读 | 直接报告 |
| section 实际内容 | section 文件字节 | 区间在 `C` 外 | 窗口内标记密文，不解释内容 |
| 符号数量/表范围 | symtab/dysymtab command | 恒可读 | 报告元数据 |
| 符号名 | nlist + 字符串表字节 | 两表都在 `C` 外 | 否则标 metadata-only |
| dyld 绑定/导出/重基 | linkedit 各区间 | 区间在 `C` 外 | 否则标记不可解析 |
| 代码签名 | `LC_CODE_SIGNATURE` 区间 | 区间在 `C` 外 | 否则标记不可校验/不可解析 |
| zerofill（如 `__bss`） | 仅 VM | 无文件字节 | 不计字节，单独标注 |

## 6. 内存样本与范围关系图

演示不依赖任何真实受保护 App，而是用 macholib 自身的 `Structure` 类在内存中构造 arm64
Mach-O（可选 fat 包装 arm64+x86_64），再用同一套类解析回来，保证“构造即合规”。
密文区用确定性 PRNG 填充，仅用于演示覆盖与熵，不代表真实密文。四种声明场景：

- `fairplay`：窗口覆盖 `__TEXT` 载荷，`__DATA`/`__LINKEDIT` 留明文（App Store 常见磁盘形态）；
- `conflict`：窗口故意扩大到越界并吞掉 `__DATA`/`__LINKEDIT`，演示范围冲突；
- `unencrypted`：`cryptid=0` 的休眠命令；
- `malformed`：`cryptid!=0` 但 `cryptsize=0` 的矛盾声明。

ASCII 范围关系图由 `demo/run_demo.py` 生成（`-` 明文可读、`#` 声明加密、`.` 区间外）。
典型 `fairplay` 单 slice 关系：

```
file 0x000000 .. 0x010000 ; crypt window 0x4000-0x8000
+------------------------------------------------------------+
|-...........................................................| header+cmds   (明文, 所有事实来源)
|---------------###############..............................| __TEXT        (头部明文 + 载荷密文)
|...............#............................................|   .__text     (密文, 入口指向此处)
|...............#............................................|   .__cstring  (密文)
|..............................---------------...............| __DATA        (全明文)
|..............................-.............................|   .__got
|..............................-.............................|   .__data
|.............................................---------------| __LINKEDIT    (全明文, 可解析)
|.............................................-..............| symtab/strtab (明文, 符号名可解析)
|.............................................-..............| dyld_info
|.............................................--.............| code_signature
|...............#............................................| LC_MAIN entryoff (位置已知, 指令不可读)
+------------------------------------------------------------+
```

读图要点：入口与 `__text` 的**位置确定、内容不确定**；依赖、头部、linkedit 确定可读；
没有任何一栏被当作“不存在”，读不到的只标“加密/不确定”。

| 文件 | 职责 |
| --- | --- |
| `demo/ranges.py` | 纯区间运算与加密覆盖分类、描述性熵；无 Mach-O 知识，便于独立审计 |
| `demo/sample_generator.py` | 内存构造合规 Mach-O（含 fat），PRNG 模拟密文；非脱壳工具 |
| `demo/analyzer.py` | 基于 macholib 读取路径的静态分析，输出带 certainty 的结构化报告 |
| `demo/run_demo.py` | 端到端演示与 ASCII 范围关系图，落一份 JSON 报告 |
| `demo/test_static_analysis.py` | 分类边界与四场景不变量测试 |
| `demo/sample_report.json` | 机器可读报告样例 |

整套交付物只做**观察、分类与不确定性标注**。任何需要明文代码才能下的结论（具体指令语义、
壳的具体厂商、隐藏 payload 的行为）都保持开放并明确标注，而不是用启发式猜测填补。
